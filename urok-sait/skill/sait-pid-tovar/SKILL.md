# Сайт під товар (односторінковий лендінг)

Ти збираєш продаючий сайт під один товар. **Дизайн уже готовий** — він лежить у `template/`. Ти не вигадуєш новий дизайн, а міняєш тільки товар: фото, тексти, ціни, колір акценту (за бажанням). Сайт одразу вміє приймати заявки в Telegram (і в LP-CRM) та передає події в Meta Pixel.

Користувачі — власники невеликих інтернет-магазинів, часто без технічного досвіду. Спілкуйся українською (або мовою користувача), простими словами, без жаргону. Не вимагай від людини технічних дій, які можеш зробити сам.

## Що лежить у шаблоні

```
template/
  index.html        сторінка товару (блоки позначені коментарями ✏️)
  thanks.html       сторінка «Дякуємо» — тут пікселю йде Purchase
  politics.html     політика конфіденційності (потрібна для реклами в Meta)
  ugoda.html        публічна оферта
  povernennya.html  обмін і повернення
  css/style.css     дизайн; колір під товар — тільки --accent, --accent-d, --accent-l
  js/config.js      назва магазину, товар, ціни, ID пікселя, адреса обробника заявок
  js/app.js         логіка (ціни, галерея, таймер, форма, піксель) — не чіпати
  img/              фото товару (placeholder.svg — заглушка, замінити)
  api/order.php     обробник заявок для хостингу Україна (PHP)
  api/config.php    🔒 секрети для хостингу: токен бота, ID групи, LP-CRM, ціни
  api/order.js      обробник заявок для Vercel (адреса /api/order)
  api/_config.js    🔒 секрети для Vercel
  api/.htaccess     забороняє відкривати секрети на хостингу
  .vercelignore     не пускає PHP-файли на Vercel
```

## Крок 1. Зібрати дані

Потрібно (якщо чогось бракує — запитай одним повідомленням, списком):

| Що | Обов'язково | Примітка |
|---|---|---|
| Посилання на товар | так | краще Prom. Temu/AliExpress без входу часто не відкриваються |
| Ціна, стара ціна | так | грн |
| Знижка за 2 шт | ні | 0 — без знижки, блок «Беріть 2» сховається сам |
| Назва магазину | так | |
| ID пікселя | бажано | довге число з Events Manager. Немає — сайт працює без пікселя |
| Токен бота | так | від @BotFather, вигляд `1234567890:AA...` |
| ID групи | так | число з мінусом, напр. `-5255376551` (у супергруп `-100...`) |
| LP-CRM: адреса кабінету, ключ API, ID товару | ні | тільки якщо людина веде замовлення в LP-CRM; офіс — якщо їх кілька |
| ФОП, телефон, email магазину | бажано | для футера і юридичних сторінок. Не дали — спитай наприкінці, до розміщення |

Голосові або «криві» повідомлення — нормально: витягни дані сам, перепитай лише незрозуміле.

**Секрети.** Токен бота і ключ LP-CRM — це ключі доступу. Записуй їх **тільки** в `api/config.php` / `api/_config.js`. Ніколи не пиши їх у `js/config.js`, `index.html`, у тексти, коміти публічних репозиторіїв чи в чат повторно. Не виводь токен повністю у відповідях — максимум перші 6 символів.

## Крок 2. Створити папку сайту

Скопіюй `template/` у нову папку з латинською назвою товару, наприклад `nozhnytsi-site/`. Далі працюй тільки в ній. Кожен новий товар — нова папка (і бажано новий чат).

## Крок 3. Товар: фото й характеристики

1. Відкрий сторінку товару (WebFetch / браузер / curl). Візьми: назву, опис, характеристики (розміри, матеріал, вага, колір, комплект), усі фото товару.
2. **Prom:** фото лежать на `images.prom.ua`. У посиланні буває розмір, напр. `..._w640_h640_...` — спробуй більший (`w1280_h1280`) або без розміру; бери найбільший, що відкривається.
3. **Temu / AliExpress / Rozetka не віддають сторінку** → знайди ту саму модель на Prom (пошук за назвою, характеристиками, схожим фото). Обов'язково покажи людині знайдене посилання і спитай: «Це точно ваш товар?» — до підтвердження не продовжуй.
4. **Хороших фото мало (менше 4)** → пошукай ще фото **саме цієї моделі** (інші продавці на Prom, сайт виробника). Чужі моделі, схожі товари, AI-картинки — не можна.
5. Завантаж фото в `img/` з іменами `1.webp`, `2.webp`, … Конвертуй у WebP і зменш до 1200 px по довшій стороні (`cwebp -q 80 -resize 1200 0`, або Python Pillow, або `sharp` — що є). Не вийшло з WebP — залиш JPG, це не критично. Видали `img/placeholder.svg`, коли всі заглушки замінено.
6. Перше фото в галереї — найчіткіше, товар цілком, світле тло. Фото з водяними знаками чужих магазинів — у кінець або не брати.

**Нічого не вигадуємо.** Розміри, матеріал, комплект, гарантію пишемо лише ті, що є на сторінці товару. Чого не знаємо — прибираємо рядок, а не фантазуємо. Наприкінці нагадай людині звірити цифри з постачальником.

## Крок 4. Текст і ціни

Заповни всі місця з коментарем `✏️` у `index.html`:

- `<title>`, `description`, `og:*` — назва товару + вигода.
- **Заголовок h1** — товар + головна вигода, до 8 слів. Підзаголовок — 1–2 речення.
- 3 короткі переваги в першому екрані, 4–6 карток «Чому його обирають» (емодзі можна змінити під товар).
- Блоки «Як це працює» / «Для кого» — коротко, з фото товару в роботі, якщо є.
- **Характеристики** — таблиця, тільки факти. «Комплект» — що реально в коробці.
- **Відгуки:** секція `#reviews` прихована (`hidden`). Вмикай тільки коли людина дала справжні відгуки (скріни, фото). **Відгуки й рейтинги не вигадуємо ніколи.**
- **Юридичні сторінки** `politics.html`, `ugoda.html`, `povernennya.html`: заміни `[ФОП …]`, `[ІПН]`, `[телефон]`, `[email]` і назву магазину в `<title>`; якщо умови доставки/оплати/повернення в магазині інші — виправ текст. Те саме — у футері `index.html`.
- Питання-відповіді: перевір, що доставка/оплата/повернення відповідають тому, як працює магазин (за замовчуванням — НП, оплата при отриманні, 14 днів). Не знаєш — спитай.
- `alt` у фото — «Назва товару — що на фото».

Мова сайту — **українська**, жива, без канцеляриту, короткі речення, звертання на «ви». Без «найкращий у світі», «100% гарантія», медичних обіцянок.

Ціни: заповни **в двох місцях**, значення мають збігатися:
- `js/config.js` → `shop`, `product`, `price`, `oldPrice`, `discount2`, `pixelId`;
- `api/config.php` (хостинг) **і** `api/_config.js` (Vercel) → `shop`, `product`, `price`, `discount2` + секрети.

Сума на сайті рахується автоматично: 1 шт = `price`, 2 шт = `2 × price − discount2`. Відсоток знижки, економія, таймер до кінця доби — теж автоматично. У HTML числа можна не міняти — їх підставить `app.js`.

Колір: за бажанням підбери `--accent` під товар/фото (теплий помаранчевий за замовчуванням підходить майже всім). `--accent-d` — темніший на 15–20%, `--accent-l` — дуже світлий відтінок. Текст на кнопці білий, тож акцент не має бути світлим.

## Крок 5. Telegram і LP-CRM

1. Впиши `tg_token` / `tg_chat` (PHP) і `tgToken` / `tgChat` (Vercel).
2. **Тестове повідомлення в групу** — одразу, ще до розміщення:
   ```bash
   curl -s "https://api.telegram.org/bot<ТОКЕН>/sendMessage" \
     --data-urlencode "chat_id=<ID_ГРУПИ>" \
     --data-urlencode "text=✅ Тест: бот підключено до сайту «<товар>». Сюди падатимуть заявки."
   ```
   Відповідь `"ok":true` — попроси людину перевірити групу. Помилки:
   - `chat not found` — бота не додали в групу, або ID без мінуса / не той. Попроси додати бота й ще раз узяти ID через @username_to_id_bot.
   - `group chat was upgraded to a supergroup` — у відповіді є `migrate_to_chat_id`, використай його (вигляд `-100…`).
   - `Unauthorized` — токен скопійовано не повністю або його перевипустили (/revoke).
   - `bot was kicked` — бота видалили з групи.
3. **LP-CRM** (лише якщо дали дані): заповни `lpcrm_domain` (без `https://`), `lpcrm_key`, `lpcrm_product_id`, `lpcrm_office` (якщо офісів кілька). Тестове замовлення в CRM створюй **тільки з дозволу людини** — воно з'явиться в її CRM. Якщо дозволила — після розміщення надішли заявку з ім'ям «ТЕСТ, не дзвонити». У повідомленні в Telegram видно, чи прийняла CRM заявку (✅ / ⚠️).

## Крок 6. Показати сайт і внести правки

1. Запусти локально: `python3 -m http.server 8080` у папці сайту (форма локально не надсилає заявки — це нормально, PHP/Vercel працюють тільки після розміщення).
2. Зроби скріни **з ширини телефона (390 px)** і з комп'ютера (Playwright / браузер), перевір: фото не обрізані криво, немає заглушок, ціни правильні, текст без повторів, кнопки видно.
3. Покажи людині (скріни або превʼю) і запропонуй правити словами: «прибери повтори», «зміни довжину на 20 см», «зроби заголовок коротшим». Вносиш, показуєш знову.
4. Перед розміщенням перевір чек-лист:
   - [ ] у `index.html` не лишилось «Назва товару», «Перевага 1», «—» в характеристиках, `placeholder.svg`, а в юридичних сторінках і футері — `[ФОП`, `[телефон]`, `[email]`;
   - [ ] ціни однакові в `js/config.js`, `api/config.php`, `api/_config.js`;
   - [ ] `pixelId` — тільки цифри; секретів немає в `js/` і `index.html`;
   - [ ] відгуки вимкнені, якщо немає справжніх.

## Крок 7. Розміщення

Запитай, який варіант обирає людина (якщо ще не сказала).

### Варіант А — хостинг Україна (ukraine.com.ua, панель adm.tools)

У `js/config.js`: `endpoint: "api/order.php"`. Видали з папки `api/order.js` і `api/_config.js` (на PHP-хостингу вони не потрібні, а `_config.js` містить токен). Запакуй **вміст** папки (не саму папку) в `<назва>-na-hosting.zip`, без `.vercelignore` і службових файлів:
```bash
cd <папка-сайту> && zip -rq ../<назва>-na-hosting.zip . -x '.vercelignore' 'api/order.js' 'api/_config.js' '*.DS_Store'
```
Архів містить токен бота — після розпакування на хостингу його треба видалити.

Якщо в людини є браузерне розширення Claude у Chrome і вона вже **сама увійшла** в кабінет хостингу (пароль ти не питаєш і не вводиш):
1. adm.tools → «Домени» → потрібний домен → «Піддомени» → створи піддомен, напр. `tovar.vash-domen.shop`. Новий домен купувати не треба: на одному домені — скільки завгодно товарів.
2. Відкрий файловий менеджер у папці піддомену, видали заглушку `index.html` хостингу (якщо є), завантаж `<назва>-na-hosting.zip`, розпакуй, **видали архів**.
3. Перевір, що `index.html` лежить прямо в корені піддомену (а не в підпапці).
4. Перевір SSL: у налаштуваннях піддомену має бути ввімкнений Let's Encrypt (зазвичай вмикається сам за 5–10 хв).
5. Надішли посилання і попередь: перші 5–10 хвилин може висіти заглушка хостингу — це нормально.

Без розширення — дай людині архів і ці кроки:
1. adm.tools: «Мої сайти» → «Додати сайт/піддомен» → вписати адресу, напр. `nozhnytsi.vash-domen.shop`.
2. «Файл-менеджер» → папка з назвою піддомену. Немає — правою кнопкою → «Створити каталог» з такою ж назвою.
3. Зайти в папку → «Завантажити файли» → обрати архів.
4. Правою кнопкою по архіву → «Розпакувати архів». У полі каталогу стерти все й поставити крапку `.` (інакше файли опиняться у вкладеній папці і сайт не відкриється).
5. Видалити архів — у ньому токен бота.

**Правки потім:** збираєш новий `<назва>-na-hosting.zip`, заливаєш і розпаковуєш так само, із заміною файлів.

### Варіант Б — Vercel (безкоштовно)

У `js/config.js`: `endpoint: "/api/order"`. PHP-файли залишаються в папці, але `.vercelignore` не пускає їх на Vercel — не видаляй `.vercelignore`.

1. Людина реєструється на vercel.com (тариф Hobby, безкоштовно).
2. У папці сайту: `npx vercel login` → дай людині посилання для входу, попроси перевірити, що це **vercel.com**, і підтвердити.
3. `npx vercel --prod --yes` (назва проєкту — латиницею за товаром, напр. `nozhnytsi`). Надішли адресу виду `nazva.vercel.app`.
4. Перевір, що `https://<адреса>/api/config.php` і `/api/_config.js` **не відкриваються** (404). Якщо відкриваються — негайно видали деплой і напиши людині перевипустити токен у @BotFather (/revoke).

Якщо твої правила не дозволяють тобі самому відправити папку з токеном на зовнішній сервіс — скажи про це прямо і запропонуй: людина пише «Задеплой сайт на Vercel, я дозволяю», або копіює твою команду в Термінал сама.

**Правки потім:** «Передеплой сайт» → `npx vercel --prod --yes`, адреса не змінюється. Свій домен можна підключити пізніше: Vercel → Project → Settings → Domains.

## Крок 8. Перевірка (разом з людиною)

1. З телефона залишити заявку на живому сайті, ім'я — «ТЕСТ, не дзвонити».
2. Заявка прийшла в Telegram-групу (і в LP-CRM, якщо підключали).
3. Після заявки відкрилась сторінка «Дякуємо» — це означає, що піксель отримав Purchase.
4. Events Manager → піксель: мають з'явитися PageView і Purchase (іноді через 20–30 хв). Для швидкої перевірки — розширення Meta Pixel Helper.

## Якщо щось не так

- **Заявка не прийшла в Telegram.** Знову надішли тестове повідомлення curl'ом (див. крок 5) — так видно, що з ботом/групою. Перевір, що на сайті правильний `endpoint` і що файли `api/` залились. На хостингу відкрий `https://сайт/api/order.php` у браузері: має бути `{"ok":false}` (405) — значить PHP працює. На Vercel — `https://сайт/api/order`: те саме.
- **На хостингу заглушка замість сайту.** Почекати 5–10 хв; перевірити, що файли розпаковані прямо в корінь піддомену, а не в підпапку, і стару заглушку `index.html` видалено; очистити кеш / відкрити в режимі інкогніто.
- **Без https або попередження «не захищено».** Почекати до 30 хв після створення піддомену; в adm.tools перевірити, що для піддомену замовлено SSL Let's Encrypt (якщо ні — замовити). Сайт має відкриватися саме через `https://`.
- **Піксель нічого не бачить.** У `pixelId` тільки цифри; блокувальник реклами в браузері вимкнено; подія може з'явитися із затримкою до 30 хв.
- **LP-CRM ⚠️.** Перевірити адресу кабінету (без `https://` і `/`), «Вхідний» ключ API (а не інший), ID товару з колонки ID і номер офісу (саме номер, не назву).

## Правила

- Один сайт = один товар = одна папка.
- Не вигадуй відгуків, рейтингів, кількості продажів, характеристик, сертифікатів.
- Не обіцяй того, чого магазин не робить (безкоштовна доставка, гарантія 12 міс.) — питай.
- Секрети — тільки в `api/config.php` / `api/_config.js`, нікуди більше.
- Не змінюй `js/app.js`, `api/order.php`, `api/order.js` без потреби: там уже є перерахунок суми на сервері, захист від ботів і передача UTM.
- Пароль від хостингу людина вводить сама. Ти його не питаєш і не зберігаєш.
